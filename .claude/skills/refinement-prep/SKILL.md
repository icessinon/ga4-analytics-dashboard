# 施策カードのリファイメント準備

Notionの「課題・施策アイディア」DB（プロダクト計画ハブ配下）のカードを、木曜のスプリントプランニングで説明できる状態に仕上げる。過去の完成例: 「ファーストビューで詳細概要が見えるようにする」「求人詳細の特定情報はモザイクで会員登録に促す」「応募フォームの入力負荷削減」。

## 手順

### 1. カードを取得する

- URLの `?p=XXXX` パラメータがピーク表示中のカードID。ハブページ本体ではなく **pパラメータのIDを notion-fetch する**
- ハブのテンプレート必須項目: 背景/現状の課題・対象ユーザー・場面・期待効果・想定インパクト/KPI・ABテスト・スコープ・概算工数・リスク

### 2. データを揃える（施策に応じて取捨選択）

- **GA4実測**（property 534098180）: `docker exec ga4-dashboard-app-local npx tsx scripts/tmp-*.ts` で集計スクリプトを書く（ローカルtsxはesbuildバイナリ不一致で不可）。既存APIの再利用も可: コンテナ内で `node -e 'fetch("http://localhost:3000/api/cv-types", {headers: {Cookie: "ga4_auth=1", ...}})'`
  - 種別ラベル: 詳細閲覧=`DL__Media__Area__{JobR|JobA|JobH}`、フォーム=`EF__{key}__Area__Header`、完了=クリックラベル `EF__{key}__Btn__{応募する|話を聞いてみる}`（JobR=人材紹介/JobA=求人広告/JobH=ハロワ）
  - view_labelは50%×1秒視認で1〜2割取りこぼす。完了は送信ボタンクリックが正
- **本体実装の現状**: `~/dev/drm-front` をExploreエージェントで調査（対象画面の構造・該当機能の有無をファイル:行番号つきで）。施策の「やること」がコードの現実と合っているか必ず確認する
- **DynamoDB実数**: `drm-front/apps/web/.env.local` のSDK認証情報（値は絶対に表示しない）。`JobDescriptions-prd` は pk=`media_{n}`・画像判定は `images[].path` の非空で見る
- **Salesforce**: 求職者=CustomObject1__c、マッチング=Matching__c、登録履歴=RegistHistory__c。売上は「7.入社済」の `MA_ClosingFee__c` −返金想定額
- **CV単価（金額換算）**: `lib/constants/cvUnitValue.ts` の係数を使う（会員登録1.8万円・人材紹介応募5,300円・広告応募7,800円・ハロワ応募2,800円）。施策インパクトは必ず円換算を添える
- **スクリーンショット**: 現状の課題が視覚的なら Playwright（モバイルは390×844）で撮り、notion-create-file-upload でカードに添付

### 3. ABテスト設計の定石

- **対象は数値が取れる側に絞る**（例: 人材紹介はSP詳細閲覧が広告の約3倍）。検出力の概算を必ず書く: 2群でp（現状率）、n/群のとき検出可能差 ≈ 2.8×√(2p(1-p)/n)。「4週で相対+X%、8週で+Y%から検出可能」の形式
- **前提改修の罠**: 詳細ページ・応募フォーム等の `getServerSideProps` は `abValue` を返しておらず `useABTest` が常にA固定になる（signupページのみ配線済み）。スコープに明記する
- 計測はラベルサフィックス方式（`__B-{issueNo}`）。GTMの要素数再スキャン問題（同数差し替えで発火しない）をリスクに書く
- 勝敗ラインと金額換算（+N人/月 ≒ +円/月）をセットで書くと判断が速い

### 4. カードを書き直す

- `notion-update-page` の `replace_content` で全面書き換え（初期ドラフトは残さない）。表は `<table header-row="true"><tr><td>` 形式
- 書き方の要点:
  - 背景は「実測データ」と「実装の現状（コード調査結果）」を分けて書く
  - 施策内容はデータに基づく優先順に番号付け。元の施策名の各要素がデータ的に妥当か検証し、妥当でなければ理由つきで格下げする
  - 数値の注意点（計測の癖・データ期間の浅さ）は隠さず書く
- プロパティ `ネクストアクション` を更新（例: 「リファイメント会で説明（◯◯は特定済み）」）。ステータスは動かさない（会での合意事項）

### 5. 報告

主要な発見（数値）を先頭に、カードに書いた施策の優先順とABテスト設計の要点を簡潔に。宿題チェックリストがあれば `- [x]` に更新する。
